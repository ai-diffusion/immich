# HANDOFF — Complete Recall (Browser Extension) — 2026-06-18

## What This Project Is

"Complete Recall" is a Manifest V3 browser extension (TypeScript, esbuild, no
backend, no network calls) that exports full AI chat conversations from
ChatGPT, Claude, Gemini, Grok, and Perplexity to local files. Output formats:
Markdown, Plain Text, JSON, HTML. Targets Chrome and Firefox/Zen Browser. The
extension auto-scrolls the page to load the entire conversation history
(platforms lazy-load older turns), converts each turn's HTML to structured
Markdown (headings, lists, tables, code blocks), extracts images/files as
downloadable assets, and writes everything via `chrome.downloads.download()`
so the chat file and its assets land in the same folder with matching names.

It is being developed as a temporary workspace inside the `ai-diffusion/immich`
monorepo at `artifacts/browser-extension/`, with a synced mirror at
`/tmp/complete-recall/` used purely to build the distributable
`extension.zip` sent to the user. **Only the immich copy is a git repo** —
`/tmp/complete-recall` is not under version control in this workflow.

## Decisions Made

- Shared-engine architecture: `capture.ts` + `dom-to-markdown.ts` hold all
  scrolling/extraction/markdown logic; each platform supplies only a
  `PlatformConfig` (selectors + small hooks) — Reason: the original
  per-platform-owns-everything design duplicated scroll/extract logic 5x and
  only ChatGPT got Markdown-quality output; the shared engine makes every
  platform get the same fidelity for free.
- esbuild bundles every content script as a self-contained IIFE — Reason:
  content scripts can't use ES module imports at runtime in MV3/MV2 without
  extra manifest plumbing; bundling statically inlines the shared libs.
- `chrome.downloads.download()` used for BOTH the main chat file and all
  assets (previously the main file used an `<a download>` click which opens
  a native Save dialog) — Reason: the Save dialog let the chat file go to a
  user-chosen folder (e.g. an Obsidian vault) while assets always went to the
  default Downloads folder; switching both to the same API call means
  everything lands in one place (the browser's default download folder),
  trading away per-file manual folder choice for guaranteed co-location.
- Asset filenames are renamed to `${chatBaseName} — ${originalAssetName}` and
  `currentExportDir` is flattened to `''` (`popup.ts` `DOMContentLoaded`
  handler) — Reason: makes every file from one export sort together
  alphabetically and identifies which chat each image/file belongs to,
  addressing the user's explicit ask for organized, consistently-named
  output.
- ChatGPT pasted-text/file chips are extracted via click-open-modal-scrape
  (`chatgpt.ts` `extractChipContent`/`extractFileAssets`), gated to
  `role === 'user'` turns only, capped at 5 chips/turn — Reason: the chip's
  full text genuinely isn't in the page DOM until clicked (confirmed by
  screenshot evidence), so a DOM-probe-only approach (Tier A) cannot recover
  it; capping protects against pathological turns with many chips slowing
  extraction.
- Markdown table conversion added to `dom-to-markdown.ts` (`case 'table'` +
  `thead/tbody/tfoot/tr/th/td` handling, with separator-row insertion logic
  for header-less tables) — Reason: the previous `default: return kids()`
  fallback concatenated all cell text with no delimiters, destroying table
  structure on export; this was the user's most concrete reported bug, fixed
  with screenshot-confirmed output.
- File-chip text is shipped as a separate downloadable asset (Blob +
  `URL.createObjectURL`), not inlined into the message Markdown — Reason:
  keeps the main chat file readable; large pasted documents (often
  hundreds/thousands of lines) would otherwise bloat every export.

## What Failed / Dead Ends

- Tier-A-only DOM probing for ChatGPT pasted-text chip content (comparing
  `innerText` vs `textContent` length to find hidden-but-present text):
  Tried first as the cheap option, failed because the chip's full content is
  not rendered anywhere in the DOM until the user clicks it open — the
  viewer modal fetches/renders it lazily. Do not retry a DOM-probe-only
  approach for this; the click-open-modal-scrape (Tier C) is required.
- Building `/tmp/complete-recall` directly after copying only the changed
  files (`popup.ts`, `dom-to-markdown.ts`) without also copying
  `formatters.ts`: failed with `No matching export in "src/lib/formatters.ts"
  for import "buildFilename"` because the mirror's `formatters.ts` was an
  older version lacking that export. Do not assume partial syncs are
  safe — when `/tmp/complete-recall` build fails after an edit, check
  whether a *dependency* file (not just the directly-edited one) is stale
  there too, and copy the whole `src/lib/` directory if in doubt.

## Known Bugs / Issues

- `src/manifest.json` → `browser_specific_settings.gecko.id` is still
  `"ai-chat-exporter@browser-ext"`, a leftover from before the rename to
  "Complete Recall". Cosmetic only (Firefox uses it as an internal extension
  ID, users never see it), but inconsistent with the rest of the rebrand.
- `src/background/service-worker.ts` still logs
  `console.log('AI Chat Exporter installed.')` instead of "Complete Recall
  installed." — confirmed baked into the current `dist/background/service-worker.js`
  build output. Cosmetic only (console log, not user-visible UI).
- `PUBLISHING.md` is entirely unrebranded — title, store listing "Name" field,
  and description text all still say "AI Chat Exporter" throughout. Will
  mislead whoever follows it to submit to the stores under the old name.
- `build.mjs` bundles `background/service-worker.ts` with esbuild
  `format: 'esm'`, but `manifest.json`'s background block does not declare
  `"type": "module"`. Currently harmless because the source file has no
  `import`/`export` statements (confirmed empty in the built output), but if
  the service worker ever gains real module syntax, the bundle may fail to
  load as a classic script in either the Chrome `service_worker` or Firefox
  `scripts` context. Worth fixing proactively (either add `"type":"module"`
  to the manifest background block, or change `build.mjs` to bundle it as
  `format: 'iife'` like everything else) before the file grows.
- Claude/Gemini/Grok/Perplexity content scripts have no attachment or
  file-chip extraction at all (see Open Questions) — any pasted text or
  uploaded file on those platforms is silently absent from exports today,
  with no placeholder, no warning, nothing. This is the same class of bug
  that was just fixed for ChatGPT, just not yet ported.

## Environment & Setup

- Runtime: Node.js (any version supporting esbuild ^0.24 / TypeScript ^5.4 —
  not pinned to a specific Node version in this repo).
- Install: `cd artifacts/browser-extension && npm install`
- Build: `node build.mjs` (or `npm run build`) — outputs to `dist/`
- Type-check only: `npx tsc --noEmit`
- Package for distribution: `npm run pack` — zips `dist/` into
  `../extension.zip` (i.e. one level above, at the workspace root)
- Dev/sideload testing:
  - Chrome/Brave/Edge: `chrome://extensions` → enable Developer mode → "Load
    unpacked" → select `dist/`. Re-run `node build.mjs` + click extension's
    Reload button after each change.
  - Firefox/Zen: `about:debugging#/runtime/this-firefox` → "Load Temporary
    Add-on…" → select `dist/manifest.json`. Resets on Firefox restart; for a
    persistent dev session use `web-ext run` (requires `npm install -g
    web-ext`).
- No environment variables are used anywhere in this project — it is fully
  client-side/local, no API keys, no backend.
- Gotcha: **two build locations must be kept in sync manually.** Edits made
  in `/home/user/immich/artifacts/browser-extension/src/...` do NOT
  automatically propagate to `/tmp/complete-recall/src/...`. After any source
  edit intended to ship in the zip handed to the user: `cp` the changed
  file(s) — and any files they import that might be stale in the mirror —
  into the matching `/tmp/complete-recall/src/...` path, then run
  `node build.mjs` in BOTH locations before zipping from `/tmp/complete-recall`.
- Gotcha: only `/home/user/immich` is a git repository in this workflow.
  `git add`/`commit`/`push` always happens from inside
  `/home/user/immich` on branch `claude/browser-extension-chat-exporter-y1OJR`,
  scoped to paths under `artifacts/browser-extension/`. Never attempt git
  operations inside `/tmp/complete-recall` — it has no `.git`.
- Gotcha: when a shared lib (`capture.ts`, `dom-to-markdown.ts`,
  `formatters.ts`, `types.ts`) changes, ALL FIVE content-script `dist/*.js`
  bundles change too (they statically inline the shared code), even if only
  one platform's `.ts` source was edited. The stop-hook git check will catch
  this — `git status` after any shared-lib edit and `node build.mjs` will
  show all 5 `dist/content/*.js` files as modified; commit all of them
  together, not just the one you meant to touch.
